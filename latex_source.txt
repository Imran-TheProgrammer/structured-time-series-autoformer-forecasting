\subsection*{Response 1A}

\textbf{My expected ordering, written before running Output 1.1.}

Stations 1--3, best to worst: Period-routed ridge $\rightarrow$ Raw Attention $\rightarrow$
Shared ridge $\rightarrow$ Sensor-specific ridge.

Station 4, best to worst: Period-routed ridge $\rightarrow$ Raw Attention $\rightarrow$ Shared ridge.
Sensor-specific ridge cannot be used here, because it has no matrix for station 4.

Why I expected this:
\begin{itemize}
  \item Period-routed ridge is told the one thing that really changes between runs, which is how
        fast the line is turning. It then uses a rule made for that speed, so I expected it to be the best.
  \item Raw Attention is not told the speed. It has to work it out from the window, and the big slow
        drift gets in the way. I expected it to be good, but behind period-routed ridge.
  \item Shared ridge uses one fixed rule for every speed, so it can only give a middle answer that
        suits no speed well.
  \item Sensor-specific ridge only knows which station the window came from. The speed still changes
        inside every station, so this does not fix the real problem, and each of its matrices is fitted
        on only a third of the windows. I expected it to be about the same as shared ridge, or slightly worse.
  \item On station 4 I expected Raw Attention to lose a little, because it never saw that sensor. The
        ridge rules depend on the speed, and station 4 turns at the same speed as the others, so they
        should lose very little.
\end{itemize}

  \item The order I expected was right for both station groups: period-routed ridge, then Raw

  \item On stations 1--3, period-routed ridge has about 4.6 times less error than shared ridge and

  \item Shared ridge and sensor-specific ridge are a tie (0.767 and 0.768). Knowing the station adds nothing.
  \item Period-routed ridge is the best on every product. Shared ridge is weakest on Products A and B
        and least bad on Product C, the slowest one.
  \item What I change in my view: the order stays, but the gaps are bigger than I thought. Raw Attention

\subsection*{Response 2}

\textbf{Selected width:} 41 samples.

\begin{figure}[H]
\centering
\outfig{2.1-1}
\caption{Output 2.1: station 2, Product C, one validation window (true period 32.0). Trend and remainder for four widths.}

\begin{itemize}
  \item \textbf{What I see in Output 2.1.} With width 17 the trend line still wiggles with the
        vibration, so part of the vibration lands in the trend and the remainder is small (spread
        0.578 m/s$^2$). With width 41 the trend is a smooth ramp and the remainder keeps the full swing
        (spread 1.572 m/s$^2$). At both ends the width-41 trend goes flat, because the end value is
        repeated there, so the ends are less reliable than the middle. After the width-41 split the
        period score has one clear peak at 32. For the raw window it has no clear peak.
  \item \textbf{Output 2.2} (training part, stations 1--3): the period is found to within one sample in
        68.7\% of raw windows. After the split it is 98.0\% (width 17), 98.9\% (25), 99.3\% (33) and
        99.8\% (41).
  \item \textbf{Output 2.3} (validation part): adding decomposition to Raw Attention lowers RMSE from
        0.460 to 0.299 on stations 1--3 (MSE 0.211 to 0.089) and from 0.706 to 0.444 on station 4. It
        helps on every product. On stations 1--3: A 0.419 to 0.276, B 0.509 to 0.327, C 0.446 to 0.291.
  \item \textbf{Why a moving average fits this world.} The drift is slow and the vibration is fast.
        Averaging over a stretch at least as long as one cycle cancels the ups and downs of the vibration
        and keeps the slow level. The simple linear head can then handle the ramp, and the encoder only
        has to handle the repeating part.
  \item \textbf{Why the oracle check is a fair way to pick the width.} The simulator knows the true
        period, so we can test directly whether the remainder still shows the repetition. It uses only
        training windows from stations 1--3, so the validation and test parts stay untouched, and the
        true period is never given to the model.
  \item The remainder is not the true repeating part. It is only what the average did not take out, and
        it still holds some slow drift, mostly near the ends.
  \item \textbf{Where this would fail.} A sudden jump in the level, for example a sensor that is
        re-calibrated in the middle of a window. The moving average spreads the jump over 41 samples, so
        the trend is wrong around it and the remainder gets a false bump that is not vibration.
\end{itemize}

\begin{figure}[H]

\begin{itemize}
  \item \textbf{Check of my code.} The worked example gives 35, 15, 25, 25, the same as expected. The
        first value is 35, so the shift runs the right way. The supplied delay scores in Output 3.1
        match the direct calculation ($4, -4, 4, -4$).
  \item \textbf{Strongest lags.} The remainder repeats most strongly at lag 16 (correlation 0.896) and
        lag 32 (0.897). These are $P$ and $2P$. The curve rises again close to lag 48, which is near
        $3P$. Halfway between these lags it is strongly negative, because a peak then meets a dip.
  \item \textbf{Why removing the drift first makes it cleaner.} In the raw window the curve has no peak
        at 16 or 32. It just slides down smoothly as the lag grows. The drift is a large ramp, and a ramp
        compared with a shifted copy of itself gives almost the same answer at every lag, so it buries
        the small vibration. Once the trend is taken out, only lags that match the cycle line up.
  \item \textbf{Why this supports delay mixing.} A few lags ($P$ and its multiples) carry almost all of
        the useful information. Picking a small number of best delays and reusing values from that far
        back is built on exactly this.
  \item \textbf{Where the assumption is wrong.} A one-off event, such as a single knock on the machine.
        It happens once, so no lag makes it line up with an earlier copy of itself. The delay mixer would
        still copy values from one cycle back, so it would miss the knock, and later it would paste the
        knock into places where nothing happened.
\end{itemize}

\subsection*{2. Validation setup}

\begin{itemize}
  \item \textbf{Split by time.} Training part: \texttt{time\_idx} 1 to 39288. Validation part: the last
        26 weeks, 39289 to 43656. A random split would let the model see the future.
  \item \textbf{Many blocks, not one.} A forecast of 168 steps starts every 24 steps in the validation
        part. That gives 176 forecasts. They all start at the same position in the daily cycle as the
        leaderboard forecast.
  \item \textbf{No look-ahead.} Every training window ends before the validation part starts. All
        scaling numbers come from the training part only.
  \item \textbf{Seeds.} Each option is trained with 3 or 5 seeds. The seed changes the starting
        weights and the order of the batches.
  \item \textbf{First rule (studies A to G).} Options whose mean RMSE is within one seed-spread of the
        best count as tied. Among tied options the cheapest wins; at equal cost, the lower mean.
  \item \textbf{Second rule (studies S1 to S10).} The option with the lowest mean RMSE wins. I changed
        the rule because the handout says accuracy is the dominant term of the ranking (Section 2.7).
  \item \textbf{Guard for the second rule.} Taking the lowest mean among many options favours lucky
        seeds. So after each group of studies, the new model replaces the old one only if the average of
        its five seeds beats the old five-seed average by more than one seed-spread.
\end{itemize}

\subsection*{3. Data processing and features}

\begin{itemize}
  \item \textbf{Target:} each seed trains two models. One learns the raw target and one learns
        $\log(1+y)$, both scaled with the training mean and spread. Each forecast is turned back to the
        original units, kept at zero or above, and the two are averaged (Study S2).
  \item \textbf{D, E, F:} $\log(1+x)$ before scaling, because they are strongly skewed (skewness 4.3,
        18.4 and 11.6). \textbf{A, B, C:} scaled only. \textbf{Flags:} left as 0 and 1.
  \item \textbf{Means and changes:} for each of the six continuous variables, the mean of the last 6
        and of the last 24 steps, and the change over 6 and over 24 steps. That is 24 more features.
        They use the present and earlier rows only and are scaled with training rows (Study S4).
  \item \textbf{Daily position:} $\sin$ and $\cos$ of $2\pi\cdot$\texttt{time\_idx}$/24$. This replaces
        the hour of the day that the hidden time stamps would have given (Study G3).
  \item \textbf{Windows:} the model reads the last 96 values and forecasts 168
        (\texttt{pred\_len} = 168). Every position in the training part starts a window: 39,025 windows.
  \item \textbf{Metrics:} RMSE, MAE and sMAPE, always in the original units.
\end{itemize}

\subsection*{4. The model}

The model is the encoder--decoder Autoformer of Wu et al.\ (2021). The code is written from scratch for
this assignment and is not copied from the public implementation; the layer layout follows the authors'
public code. It reuses the Task 1 \texttt{SeriesDecomposition} and \texttt{aggregate\_delays}, and the
course's \texttt{delay\_scores}. How the AI assistant was used is stated in the last section.

\begin{itemize}
  \item \textbf{Series decomposition.} A centered 25-step moving average on the input and after every
        sub-layer, six in total. 25 is one daily cycle plus one, so the daily cycle is averaged out of the
        trend. The encoder keeps the remainder. The decoder adds up the trends it removes.
  \item \textbf{Auto-correlation.} Three blocks: encoder, decoder, and decoder reading the encoder.
        Each one scores every delay with an FFT, keeps the best $k=\lfloor \ln L\rfloor$ delays (4 in
        the encoder, 5 in the decoder), turns the scores into weights, and adds the shifted copies.
  \item \textbf{Size.} One encoder layer, one decoder layer, width 16: 8,933 parameters per model.
        Wider, deeper and longer-trained versions were all worse (Studies D, E, S1, S1b).
  \item \textbf{Where the optional file enters.} The 36 known-ahead features (10 variables, 24 means
        and changes, 2 for the daily position) go through a small two-layer network (36 to 32 to 16) and
        are added to the inputs of both encoder and decoder. For the 168 future steps the decoder sees
        the values of those same steps. The first version used one linear layer; the two-layer network
        was the largest single gain (Study S3).
  \item \textbf{One change from the paper: the starting trend} (Study A). The paper starts the future
        trend at the mean of the input window, so it assumes the level stays where it is for all 168
        steps. Mine starts at the last observed value. The gap between that value and the decoder's
        own first step fades at one learned rate.
  \item \textbf{Smaller differences:} delays are chosen per window, as in Task 1; one head; a learned
        temperature for the delay weights.
  \item \textbf{Training:} AdamW, one-cycle learning rate up to 0.003, gradient clipping at 5, batch
        64, squared error on the scaled target, dropout 0.1, 4 epochs. Learning rate, dropout and epochs
        were tested (Studies S6, S8). The rest follows the Task 1 harness.
\end{itemize}

\begin{itemize}

        poor guess for the next seven days.
  \item Both fading starts are far ahead of the paper's start: 60.07 and 60.85 against 119.75.
  \item The paper's 119.75 is partly a dropout effect, so I checked it (Table~\ref{tab:q2-dropout}).
        With dropout on, as in training, those models fit the training windows about as well as the
        others. With dropout off, as in forecasting, they forecast 0.78 standard deviations too
        high. The fading starts show no such gap.
  \item Without dropout the paper's start gives \pmv{67.15}{1.21}. It is still behind the fading level
        (\pmv{61.51}{1.28}) and the anchor (\pmv{59.71}{0.92}). So the fading starts win either way: in the fair
        comparison by about 6 (fading level) and 7 (anchor).
  \item My reading: the paper's start adds the window level at the very end, and no layer of the decoder
        ever sees that level. So the decoder cannot correct it when the level does not last.
  \item Fading level and anchor are tied on overall RMSE and cost the same, so I took the lower mean.
        The anchor is also much better in the first hours: one step ahead its RMSE is 15.9, against
        46.6 for the fading level and 16.7 for repeating the last value.
\end{itemize}

\subsection*{7. Where the three metrics disagree}

\begin{itemize}
  \item \textbf{The ranking flips in Study S2.} RMSE prefers the average of a raw and a log model
        (56.70 against 57.56 for log alone). MAE and sMAPE prefer log alone (38.41 against 40.50, and
        48.78 against 52.50).
  \item \textbf{Where each one errs} (Study B, validation): 29\% of the true values are below 30. There
        the mean absolute error is 32.9 with the raw target and 19.7 with log. 11\% are above 200.
        There it is 100.8 with raw and 114.4 with log.
  \item \textbf{The same flip for the linear fit:} RMSE prefers the raw target (72.11 against 73.53)
        while MAE and sMAPE prefer log (48.60 against 53.49, and 59.28 against 67.50).
  \item \textbf{Why:} RMSE squares the error, so a few very high hours decide it. sMAPE divides by the
        level, so the many low hours count as much as the high ones. MAE sits between the two.
  \item The leaderboard ranks by RMSE, so I chose on RMSE and used the other two as a check.
\end{itemize}

\subsection*{10. Limits}

\begin{itemize}
  \item \textbf{Too high on average.} The mean error of the submitted average is $+9.8$. It grows with

  \item \textbf{Validation was used many times} (about 400 training runs). The five-seed checks guard

  \item The validation part is one stretch of 26 weeks. Other times of the year are not tested.
  \item The submitted models never trained on the last 26 weeks. Study S9 found no steady gain from

  \item In Study A the anchor and the fading level are tied on overall RMSE. I added the anchor after a

\end{itemize}

\textbf{Q2.1 Lags against positions.}
\begin{itemize}
  \item \textbf{Lags are better} for a signal that repeats with a steady period inside the window. Every
        pair of points one period apart is related for the same reason, and one score per delay pools
        all of them. My Task 1 result (validation, stations 1--3): delay mixing against Attention gave
        RMSE 0.212 against 0.460 on raw input and 0.199 against 0.299 on decomposed input.
  \item \textbf{Lags lose something} when what matters is one place, not a spacing: a single event, a
        change point, a pattern that happens once. Attention can give that one position a high weight.
        Delay mixing shifts the whole window by the same amount and joins its end to its start.
  \item \textbf{Slow drift of the period:} delays are scored afresh for each window, so they follow a
        period that changes from window to window. In Task 1 the period changed between runs and
        delay mixing still worked.
  \item \textbf{Drift inside one window:} no single delay lines the cycles up. The best score gets low
        and wide and the mix blurs. Attention is not tied to one spacing, so it suffers less.
  \item In Task 2 the cycle is weak, so the delays add little by themselves: without the optional file
        the selected model scores 84.85, close to always predicting the training mean (88.74).
\end{itemize}

\textbf{Q2.2 The moving-average trend.}
\begin{itemize}
  \item \textbf{What it assumes:} the trend is smooth and changes slowly compared with the 25-step
        width. Anything faster is counted as seasonal.
  \item \textbf{Boundaries:} the ends are padded by repeating the end value, so near the forecast start
        the trend leans toward the last value and lags a rising or falling level.
  \item \textbf{Curvature:} an average cuts peaks and fills valleys, so a bending trend is flattened.
  \item \textbf{Abrupt shift:} a jump is spread over 25 steps. The trend shows a ramp that never
        happened and the remainder gets a false bump. My series has such jumps.
  \item \textbf{Alternative:} one-sided exponential smoothing with a learned rate. It assumes recent
        values matter most and needs no values to the right of the forecast start, so no padding
        there. What I give up: it lags the trend everywhere, and it no longer cancels a known cycle
        the way a 25-step average cancels a 24-step cycle.
\end{itemize}

\textbf{Q2.3 Decomposing once or in every block.}
\begin{itemize}
  \item \textbf{What repeating buys:} a one-time split only cleans the input. Inside the network each
        layer adds its output back to the stream, and slow parts can come back. Removing them after
        every sub-layer keeps the stream free of drift, so delay scoring is not swamped by it. It
        also lets the decoder build the trend step by step.
  \item My evidence from Task 1: the repeat at one period only showed after the trend was removed
        (correlation 0.896, Output 3.2), and decomposition inside the network cut validation RMSE
        from 0.460 to 0.299 (stations 1--3).
  \item \textbf{Where it hurts:} when the slow part is itself the signal. Every decomposition removes
        the level again and the encoder throws it away, so the decoder cannot see how high the
        window is. In Task 2 I think this is why the paper's start is behind (67.15 against 59.71
        without dropout, Table~\ref{tab:q2-dropout}).
  \item Each moving average also has an edge error, and repeating it stacks those errors. This may be
        why my error rises at the very last lead.
\end{itemize}

\textbf{Q2.4 The number of delays, $k = c\log L$.}
\begin{itemize}
  \item $k$ is how many delays are kept. In my model $k=\lfloor\ln L\rfloor$: 4 in the encoder ($L=96$)
        and 5 in the decoder ($L=216$).
  \item \textbf{Larger $k$:} more spacings are mixed, also weak ones that are mostly noise. The output
        gets blurred and costs more.
  \item \textbf{Smaller $k$:} sharper and cheaper, but it can miss a real period or bet on one wrong
        delay. Mixing a few delays is a hedge under squared error.
  \item \textbf{$\log L$ is convenient, not principled.} It keeps $k$ small as the window grows. But how
        many delays are needed depends on how many real periods the signal has, not on the window
        length. $k$ should be at least the number of periods one wants to catch, with their multiples.
  \item \textbf{Experiment} (Table~\ref{tab:q2-reflect}): $c$ = 1, 2, 3 gave RMSE 57.12, 57.61, 58.24.
        More delays did not help. This series has one weak daily cycle, so few delays are enough.
\end{itemize}

\textbf{Q2.5 One shot or feeding predictions back.}
\begin{itemize}
  \item \textbf{One shot} (my model): all 168 steps come out together. No error is fed back, and the
        model is used exactly as it was trained. Errors at neighbouring leads are alike, but they do
        not build on each other.
  \item \textbf{Feeding back:} each step uses earlier predictions, so errors pile up with the horizon.
        The model is trained on true inputs but used on its own outputs. One early miss drags all
        later steps, so the errors along the horizon are strongly linked.
  \item \textbf{Feeding back is better} when the one-step rule is simple and stable, noise is small and
        the horizon is short. \textbf{One shot is better} for long horizons, heavy tails and when
        known-ahead inputs exist for every step.
  \item As the horizon grows, one shot wins. Here repeating the last value has RMSE 16.7 one step ahead
        but 138 at 48 steps, while one seed of my model stays between about 39 and 62 from lead 24 on.
  \item I did not train a feed-back version, so this answer is reasoning, not a measured comparison.
\end{itemize}

\textbf{Q2.6 Window-relative normalisation.}
\begin{itemize}
  \item \textbf{What is destroyed:} the window's own level and spread, that is, how high and how lively
        the window is compared with the whole series.
  \item \textbf{When it matters:} when the future depends on that level. In a series that returns to a
        fixed mean, a high window should come down and a low one should go up.
  \item \textbf{Helps a lot:} when level differs between series for reasons that do not change the
        shape. In Task 1 the stations had different offsets, and anchoring let one model serve the
        unseen station 4.
  \item \textbf{Loses something essential:} a series that returns to a fixed mean. The best forecast is
        the mean plus a fading share of the present gap. After normalisation the model cannot know
        the gap.
  \item \textbf{Experiment} (Table~\ref{tab:q2-reflect}): with window-relative normalisation RMSE is
        93.08 against 57.12 without. Putting the window level back assumes the level stays, and in
        this series it does not.
\end{itemize}

\textbf{Q2.7 Variables known up to the origin, or across the horizon.}
\begin{itemize}
  \item It changes \textbf{where} they enter, not only how much they help. A variable known only up to
        the origin can only enter with the history, in the encoder. A variable known across the
        horizon can also enter the decoder at the steps being forecast.
  \item \textbf{Experiment} (Table~\ref{tab:q2-optional}): no file 84.85, past only 85.70, past and
        future 45.94. The same variables are almost useless in the first case and decisive in the second.
  \item \textbf{Useful only when known ahead:} a variable that changes fast and has little memory, so its
        past says little about its future. The flags are like this (correlation with their own value
        24 steps earlier: 0.04 to 0.23).
  \item \textbf{Equally useful in both:} a variable whose future follows from its past, such as the
        position in the daily cycle or a fixed schedule. Knowing it ahead adds nothing new.
\end{itemize}

\textbf{Q2.8 No calendar.}
\begin{itemize}
  \item \textbf{What is lost:} hour of day, day of week, month and holidays. The model cannot be told
        ``it is Monday morning'' or ``it is winter''.
  \item \textbf{How I recovered the cycle:} from the data (Figure~\ref{fig:q2-period}). After removing a
        25-step average the autocorrelation peaks at lags 24, 48, 72 and 96, and the mean by
        \texttt{time\_idx} mod 24 moves between 87 and 113. So I used $\sin$ and $\cos$ of the position
        in a 24-step cycle, and a 25-step moving average.
  \item \textbf{Experiment} (Table~\ref{tab:q2-reflect}): 57.12 with the daily features, 58.87 without.
  \item \textbf{What must hold:} equal steps with no gaps (given); a cycle length that stays the same
        over the whole series; and enough cycles to average out noise (1,637 in the training part).
  \item A 7-day effect is too weak to trust, and the training part holds only four and a half yearly
        cycles, so I used neither.
\end{itemize}

\textbf{Q2.9 Structural methods against a decomposition Transformer.}
\begin{itemize}
  \item \textbf{Structural methods} fit few numbers under strong assumptions. They win when the series
        is short, noisy and regular.
  \item \textbf{A Transformer} assumes less and fits thousands of numbers. It needs many windows and a
        pattern that the simple model cannot express. It also takes extra inputs easily.
  \item \textbf{The crossover} moves toward the Transformer as the series gets longer, the noise gets
        smaller and the structure gets richer.
  \item \textbf{Before training I would check:} windows against parameters; how regular the series is
        (autocorrelation, share of a clean cycle); and the score of cheap baselines.
  \item \textbf{My evidence:} a linear fit with 13 numbers on the optional file (72.11) beats my
        Autoformer without the file (84.85, with 13,514 parameters for one seed). With the file, the
        Autoformer (45.94 for one seed) beats the linear fit. In Task 1 a hand-built linear model (0.166) beat every neural
        model (best 0.199). More size did not help here: on the first model, width 64 with 85,125 parameters gave
        59.03 against 57.12 for width 16.
  \item I did not fit ETS or SARIMA. The classical side of this comparison is only the linear fit and
        the simple baselines of Table~\ref{tab:q2-base}.
\end{itemize}
